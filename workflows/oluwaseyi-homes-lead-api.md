# Oluwaseyi Homes & Properties - Lead API

- **n8n workflow:** `JILrnB7YXeag8oAk`, "Oluwaseyi Homes & Properties". All of this app's n8n logic lives in this one workflow; this file covers its **Lead webhook** trigger. Saved copy: `oluwaseyi-homes-and-properties.json`. (The old form-only `HOdw6e22lN7Gji7n` is untouched and switched off.)
- **Trigger:** Webhook, `POST`, JSON body, Header Auth, `responseMode: responseNode`
- **Path:** `/webhook/oluwaseyi-homes-lead` (production, workflow must be active) or `/webhook-test/...` (test)
- **Called by:** Next.js API route `src/app/api/leads/route.ts` only. The browser never calls n8n.
- **Stores in:** Supabase (`leads`, `email_codes`, `audit`) through two database functions, plus a row in the Google Sheet.
- **Needs:** `supabase/migrations/0002_enquiry_codes.sql` applied, and the n8n credential "Oluwaseyi Homes Supabase" (type `supabaseApi`).

Header: `x-webhook-secret` (override with `N8N_WEBHOOK_HEADER`), value in `N8N_WEBHOOK_SECRET`.

## Step 1: send the enquiry (a 6-digit code is emailed)
```json
{
  "firstName": "Ada", "lastName": "Obi", "email": "ada@example.com", "phone": "08012345678",
  "enquiryType": "Rent", "propertyType": "Apartment", "location": "Yaba", "budget": "1,500,000",
  "moveInDate": "2027-01-15", "facilities": "Prepaid meter,CCTV", "assistance": "yes",
  "listingId": "P-0001", "source": "instagram", "acknowledged": "yes", "specialRequirement": "Near the university"
}
```
| Field | Required | Rules |
|---|---|---|
| firstName, lastName | yes | non-empty |
| email | yes | valid email |
| phone | yes | 7-20 digits (leading `+`, spaces, `()-` allowed) |
| enquiryType | yes | Rent, Buy, Invest |
| propertyType | yes | Apartment, Duplex, Semi-detached, Land, Office, Shop, Others |
| acknowledged | yes | must be `yes` (customer acknowledges the platform introduction) |
| moveInDate | no | `YYYY-MM-DD` |
| inspectionDate, inspectionSlot | no | the day (`YYYY-MM-DD`) and `Morning`, `Afternoon` or `Evening` the customer would like to inspect the chosen property; kept only when `listingId` is a published property |
| siteUrl | no | the website address the visitor was on; links in emails use it, so they open the same site |
| facilities | no | comma-separated names |
| assistance | no | `yes` = optional tenant assistance requested (Rent only) |
| listingId | no | the property's code; unknown codes leave the lead unlinked |
| location, budget, source, specialRequirement | no | free text |

Response `200`: `{"success":true,"data":{"step":"code","message":"We sent a 6-digit code..."},"error":null}`

## Step 2: confirm the code (the lead is registered)
```json
{ "action": "verify", "email": "ada@example.com", "code": "123456" }
```
Response `200`: `{"success":true,"data":{"reference":"OHP-L-000001","trackToken":"<64 hex characters>","message":"Thank you. Your enquiry is registered..."},"error":null}`

`trackToken` is the customer's private link to follow the enquiry: `<website>/track/<trackToken>`. The confirmation email carries the same link.

`reference` is the Lead ID, generated by the database.

## Dashboard actions (sent by the website server only, after it has checked the person's permission)
- `{ "action": "send-email", "to": "<address or \"team\">", "subject", "heading", "paragraphs": [], "rows": [[label, value]], "button": { "label", "url" } or "buttons": [up to three], "footnote" }`:
  sends one branded email. Used for the owner's contact details to a customer, the owner acknowledgement link, invoices, receipts and the team notice
  when an owner reports a completed deal. Response `200` `{"data":{"message":"The email was sent."}}`, `502` if Gmail failed, `400` if the address, subject or heading is missing.
- `{ "action": "follow-up", "leadId", "actor", "siteUrl" }`: the database function `create_follow_up` makes one-time links for the customer and the owner,
  and each is emailed asking whether the inspection took place and whether the deal completed. `409` if the lead has no released contact or is already closed.

## Daily follow-ups (Schedule trigger, 09:00 Lagos time)
Runs `create_follow_ups`: flags possible unreported deals, then emails a follow-up to both sides of every open lead whose contact was released
at least 3 days ago, at most weekly and at most 4 times. Answers come back through the page `/r/<token>` on the website, not through n8n.

## Errors (always `{ "success": false, "data": null, "error": "..." }`)
| Case | Status |
|---|---|
| Invalid input, or a code that is not 6 digits | 400 |
| Wrong, expired or used code (message says which) | 400 |
| More than 5 codes requested for one email in an hour | 429 |
| The code email could not be sent | 502 |
| Supabase unreachable or the database functions missing | 500 |

Missing or wrong Header Auth is rejected by n8n itself with 403 (not our shape); the API route maps that to its own error.

## Rules enforced in the database
A code works for 10 minutes, is stored only as a hash, is cancelled by a newer code, and dies after 5 wrong tries.
The lead is created with a verified email and the customer's acknowledgement time, and its history rows are written by a trigger.

## Flow
Webhook → Validate and normalize → Valid input? → Which step?
- **request:** Create email code (Supabase function) → Code created? → Email code → Respond 200. Otherwise Respond 429 / 502.
- **verify:** Register lead (Supabase function) → Lead registered? → Prepare lead → Save lead to sheet → Respond 200 → Build emails → Email client + Email team. Otherwise Respond 400.
- **send-email:** Send email? → Send email → Respond 200 (or 502).
- **follow-up:** Follow-up now? → Create follow-up for lead → Any follow-up? → Respond 200 → Build follow-up email → Email follow-up.
- **schedule:** Daily follow-ups → Create follow-ups → Build follow-up email → Email follow-up.
- Either Supabase call failing → Respond 500. Invalid input → Respond 400.

The sheet row and the two emails come after the lead is stored, so a sheet or email problem never loses a lead or changes what the caller sees.

## Google Sheet
Sheet `YOUR_GOOGLE_SHEET_ID` (the real ID is in `.env` as `LEAD_SHEET_ID`), one tab per enquiry type (Rent gid 0, Buy 1705566378, Invest 1194300972).
Columns written: Timestamp, Name, Email Address, Phone Number, what are you looking for, Property Type, Location, Budget, Special Requirement.
"Special Requirement" also carries the move-in date, facilities, assistance request, Lead ID, property and source.
